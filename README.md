# timo

A small Pomodoro timer for macOS, Windows and Linux. One Go executable runs both a terminal REPL and a browser dashboard; both use the same JSON data and timer state.

## Install as an app (recommended)

You can install **Timo** and launch it from the Windows Start Menu or from macOS Finder/Spotlight, without opening a terminal. See **[INSTALL.md](INSTALL.md)** for installation, updates, uninstallation, security notes, and build instructions.

- **Windows 10/11 x64:** extract `timo-v1.0.4-windows-install.zip`, then double-click `Install Timo (Windows).cmd`. Or double-click `dist/timo-app-windows-amd64.exe` without installing.
- **macOS Apple Silicon/Intel:** extract the appropriate `timo-macos-*.app.zip` and move `Timo.app` to Applications. It opens the browser dashboard for you.
- **Terminal remains supported** on both platforms. `timo desktop` opens the graphical host, and `timo stop-desktop` stops the desktop host; `timo web` still runs a foreground server.

The graphical launcher opens a browser tab and runs its server in the background; it is not yet a native standalone webview window. There is no Electron, Tauri, Node.js or frontend build step. The JSON file location and format are unchanged.

## Download and run

Unzip the release. Open a terminal in the extracted `timo` folder and use the executable for your system:

| Platform | Command |
| --- | --- |
| macOS Apple Silicon (M-series) | `chmod +x dist/timo-darwin-arm64 && ./dist/timo-darwin-arm64` |
| macOS Intel | `chmod +x dist/timo-darwin-amd64 && ./dist/timo-darwin-amd64` |
| Windows x64 (PowerShell) | `.\dist\timo-windows-amd64.exe` |
| Windows ARM64 | `.\dist\timo-windows-arm64.exe` |
| Linux x64 | `chmod +x dist/timo-linux-amd64 && ./dist/timo-linux-amd64` |

The downloaded macOS binaries are not signed or notarized. If Gatekeeper blocks them, compile the included source locally using Go instead of disabling system protections.

Start the terminal REPL, then type:

```text
timo > start        # live countdown begins automatically
                     # press Enter to return to the command prompt
timo > pause
timo > resume
timo > stats 30
timo > set focus 30
timo > set break 5
timo > set color '#C0B2E8'
timo > set theme system
timo > set grain on
timo > web          # opens the browser dashboard
timo > quit
```

`web` opens the browser at **http://127.0.0.1:8765**. The local server stays running until you quit the REPL. To use just the browser, run `timo web` from your shell, such as `./dist/timo-darwin-arm64 web` or `.\dist\timo-windows-amd64.exe web`. Quit this standalone server with Ctrl+C.

### Terminal commands

| Command | Result |
| --- | --- |
| `start`, `pause`, `resume` | Control the timer (`start` and `resume` show a live countdown in the REPL) |
| `reset`, `skip`, `stop` | Reset current phase, skip it, or return to focus |
| `focus`, `break`, `long_break` | Select a session type |
| `watch`, `status` | Return to the live countdown / show a one-off status |
| `stats [days]` | Print an activity chart, default 7 days |
| `settings` | Show current settings |
| `set focus 25`, `set break 5`, `set long 15` | Set durations, in minutes |
| `set every 4` | Set long break interval |
| `set color '#C0B2E8'` | Set accent colour (hex) |
| `set theme dark` | Set appearance: `dark`, `light`, `system` |
| `set grain on` | Enable background grain motion (`on`, `off`) |
| `web`, `where`, `help`, `quit` | Browser, file location, help, exit |

Most commands also work directly from the shell, e.g. `timo stats`, `timo start`. Direct shell commands return immediately and do not enter the live countdown. In the REPL, you can press Enter to leave the live countdown without pausing the timer. If you type a command while the countdown is visible, it is still processed. On a restarted REPL, a previously running timer also opens its live countdown automatically.

**Windows 10 note:** The live countdown updates once per second on a single console line using a carriage return, without ANSI line-clearing commands. The browser continues to read the same persisted end timestamp; no additional JSON writes are generated by each countdown tick.

## Browser interface

The web UI uses vanilla HTML, CSS and JavaScript. There is no frontend build step. The redesigned interface uses a restrained background adapted from your GrainField v2.1 preview: two embedded WebP texture tiles for dark/light, stationary colour clouds, and optional slow grain motion. Motion defaults to **off** and respects `prefers-reduced-motion`; it pauses when the tab is hidden. Fonts are platform-native and no font files are bundled.

The browser includes timer controls, focus/short/long-break switching, period-based activity statistics, session history, CSV session exports, complete JSON backups, durations, accent colour presets, light/dark/system appearance and the grain-motion toggle. Settings save to the same JSON file as the terminal and appear in both interfaces.

### Mobile layout

The browser UI adapts to narrow screens (280–430 CSS pixels), tablets and short landscape screens without a separate frontend. On phones, navigation moves to its own row; the timer and its 44–48px-high controls stay readable; duration fields use two columns; statistics stack and the activity chart fits the available width without horizontal scrolling. Longer ranges are grouped into seven-day periods where necessary. The all-time summary still counts every session, while its chart shows up to the last 90 days to avoid rendering thousands of bars. The layout accounts for display cutouts and reduced-motion preferences.

Mobile layout is **not** the same thing as connecting a separate phone to the computer running timo: the web server is intentionally restricted to loopback. Do not expose its unauthenticated write API to your Wi-Fi or the internet. On the desktop you can inspect phone layouts using the browser's responsive design mode.

Open the browser using `timo web`, **not** by double-clicking `web/index.html`. Browsers cannot directly read and safely update the app's JSON file through `file://`. HTML/CSS/JS are embedded inside the Go binary; rebuild the binary after editing them.

## Data and compatibility

Your data is stored in a readable `data.json`. New installations use:

- macOS: `~/Library/Application Support/timo/data.json`
- Windows: `%AppData%\timo\data.json`
- Linux: `~/.config/timo/data.json`

**Upgrading from Pomo v1.0:** if no timo data file exists but `pomo/data.json` does, timo automatically continues using the existing Pomo file (and its `.lock`) in place, without copying, so your timer, history and settings remain available. You can confirm the location with `timo where`. The JSON schema keeps version 1; missing theme settings in older files default to dark and motion off. For long-term use, stop the old Pomo process before relying on new appearance settings, since the old binary doesn't preserve unknown JSON fields.

To choose a different location, set `TIMO_DATA_FILE` to an absolute path. `POMO_DATA_FILE` is also accepted for backwards compatibility if the new variable is unset.

The Go store takes an OS file lock for every read/settle/update/write transaction, uses an atomic file replacement, and records completed sessions exactly once. Browser settings updates include a revision check so concurrent edits are not silently overwritten. The data file is not rewritten once per second: the timer is based on a persisted end timestamp. Breaks don't start automatically, and skipped sessions don't count toward stats.

This protects concurrency **on the same machine**, not synchronization between machines via cloud folders. Avoid editing the JSON file by hand while timo is running.

## Build from source

Go 1.23+ works with the source; there are no third-party dependencies.

```sh
go test ./...
go test -race ./...  # native host tests
go vet ./...
go build -o timo .
./timo
```

Windows PowerShell:

```powershell
go test ./...
go build -o timo.exe .
.\timo.exe
```

To rebuild the release executables:

```sh
GOOS=darwin GOARCH=arm64 go build -o dist/timo-darwin-arm64 .
GOOS=darwin GOARCH=amd64 go build -o dist/timo-darwin-amd64 .
GOOS=windows GOARCH=amd64 go build -o dist/timo-windows-amd64.exe .
GOOS=windows GOARCH=arm64 go build -o dist/timo-windows-arm64.exe .
GOOS=linux GOARCH=amd64 go build -o dist/timo-linux-amd64 .
```

### Docker (optional)

```sh
docker build -t timo .
docker run --rm -p 127.0.0.1:8765:8765 -v timo-data:/data timo
```

The Docker volume is separate from the host's default JSON file. Do not expose this unauthenticated local API to the public internet. Docker Desktop bind-mount locks should not be assumed to coordinate with host macOS locks; keep concurrent writers on the same host OS.

## Tests and troubleshooting

Run `go test ./...`, `go test -race ./...`, `go vet ./...`, and `node --check web/app.js` (if Node is installed). For responsive visual QA, use your browser device emulator at 280, 320, 375, 390, 430, and 768 CSS pixels, plus a landscape viewport. Verify no page-wide or chart horizontal scrollbar, all navigation and export controls remain reachable, and CSV/JSON downloads work. These are manual checks, not a claim of physical-device testing. The tests cover timer transitions, persistence, exactly-once recording, simultaneous updates, invalid JSON preservation, API protections, settings conflicts, asset serving and migration-compatible appearance settings.

If the web UI says offline, check that `timo web` is still running and that port 8765 is free. You can run another port with `timo web --port 8989`. Timer durations change on the next session unless you reset an idle session. Set `NO_COLOR=1` for terminals that don't support ANSI colours.

### v1.0.2 — Terminal countdown fix

The Windows/macOS/Linux REPL displays a live countdown immediately after `start` and `resume`, including when reopened during an active session. Press Enter to get a command prompt while the timer keeps running. `watch` restores the live display. An input reader shared across the REPL prevents concurrent reads or swallowed commands when a session ends.

### v1.0.3 — Browser refinements and data export

The connection badge is removed; connection failures continue to appear as error messages. The Activity chart fits its container without horizontal scrolling: 7-day ranges show daily bars, 30-day ranges show daily bars on wide screens and seven-day groups on narrow screens, and the all-time graph groups up to the last 90 days into seven-day periods (while all-time statistics count all sessions). The countdown separator has its own spacing, including on phones.

The Statistics header provides **Export CSV** (completed sessions within the selected date range, with exact timestamps, duration and IDs) and **Backup JSON** (the latest full state, including settings, the current timer and all history). Both download via the browser from a fresh snapshot and never write to the source JSON file. CSV contains a header even if there are no completed sessions; JSON can be used as a manual backup (there is no import UI).
